# Релиз

Панель раздаётся через PyPI, потому что установка обязана быть одной командой
на любой машине. Всё остальное — установщик, дерево плагина, зависимости под
конкретную Houdini — приезжает уже оттуда.

## Что происходит при установке у человека

Три шага, и только первый требует PyPI:

1. `uvx --from houdini-agent-panel …` — качает пакет и запускает его инсталлятор,
   ничего не оставляя в системе.
2. Инсталлятор находит все Houdini на машине и для каждой ставит панель **в её
   собственный Python**: `hython -m pip install --target <data>/deps/py3.11`.
   Отдельным деревом на версию, потому что `pydantic` тащит скомпилированное
   ядро, а у Python 3.11 (H20.5) и 3.13 (H22) разные ABI.
3. Пишет package json в prefs каждой Houdini.

Отсюда следствие, которое легко упустить: **версия на PyPI должна быть той же,
что запускает инсталлятор.** Шаг 2 просит у pip ровно `houdini-agent-panel==<своя
версия>`. Выложить колесо, но не выложить sdist, или выложить под другим
номером — значит получить установку, которая падает на втором шаге, уже
показав человеку, что всё идёт хорошо.

## Порядок

```bash
# 1. Версия в одном месте — python/houdini_agent_panel/__init__.py и pyproject.toml
#    должны совпадать. Проверяется тестом.
.venv/bin/python -m pytest -q

# 2. Сборка обоих дистрибутивов. sdist обязателен: без него машины, для которых
#    нет колеса, останутся без панели.
rm -rf dist && uv build -o dist

# 3. Метаданные и содержимое
.venv/bin/python -m twine check dist/*

# 4. Проверка на настоящей Houdini до публикации, из локального колеса
uvx --from ./dist/houdini_agent_panel-*.whl python -m houdini_agent_panel install --find-links "$(pwd)/dist"

# 5. Публикация
UV_PUBLISH_TOKEN=$(grep -E '^PYPI_TOKEN=' ~/Github/may-hub/.env | cut -d= -f2-) uv publish dist/*
```

Токен живёт только в `~/Github/may-hub/.env` (chmod 600, вне git) и читается в
момент использования — как и все остальные секреты в этом хозяйстве.

## Что проверить руками перед публикацией

Тесты этого не ловят, а сломается у всех сразу:

- **Дерево плагина попало в колесо.** `houdini_agent_panel/houdini/` с
  `python_panels/*.pypanel` и обоими `python3.*libs/uiready.py`. Без него
  Houdini не покажет панель вообще, а установка отработает без единой ошибки.
- **Панель поднимается в живой Houdini.** Ни один юнит-тест этого не проверяет:
  вне Houdini asyncio стоковый, сертификаты системные, Qt один — а внутри всё
  три раза не так (см. [`facts/houdini.md`](facts/houdini.md) §9).
- **Номер версии.** После публикации его не переиспользовать: PyPI не даёт
  перезалить файл под тем же номером, только выпустить следующий.

## Фид оповещений

Адрес по умолчанию ведёт в этот репозиторий, и пока репозиторий приватный,
`raw.githubusercontent.com` отдаёт анонимному клиенту 404 — то есть оповещений
у пользователей просто нет. Панель от этого не ломается, сетевая ошибка
гасится. Когда канал понадобится — либо опубликовать репозиторий, либо
положить `announcements.json` на любой публичный адрес и поменять
`DEFAULT_FEED_URL`. Студия может переопределить его переменной `HAP_FEED_URL`,
не пересобирая пакет.
